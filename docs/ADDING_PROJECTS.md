# Adding a project from the back office

Open `/fill-db` (Ctrl+A on any page), sign in, choose "Add project".

## Fields that matter

| Field | What to write |
| --- | --- |
| Title | The project name as a client would say it. No colons or pipes, they break the URL slug. |
| Description | Two or three sentences. It is the fallback if the one-sentence summary is empty. |
| Case study, Type | **Client work** for anything delivered for someone else. **Personal project** for products, experiments and study work. |
| Case study, Service | Tick Web, Data or both. This drives the filters and which service page lists the project. |
| Client or context | Company name, or "Personal project". |
| Summary | One sentence. Shown on the card and under the title. |
| Challenge, What you built, Outcome | Three short paragraphs: the problem in the client's words, what you built and with what, what changed. |
| Key numbers | 3 or 4 lines in the form `value | label`. Only numbers you can defend in a call. |
| Key features | One per line, five or six at most. |
| Live URL | The running site or demo. It shows a "View live demo" button. |
| Hide this project | Keeps the project in the database but removes it from every page. |

## Screenshots

- Use **1440 x 900** (16:10), taken at 100% browser zoom, with realistic data and no cookie banner or dev tools.
- Cover image first: the most recognisable screen (home page or main dashboard).
- Five to six screens are enough: overview, the main workflow, a data or admin view, a mobile view if it matters.
- Give every screen a caption of two to five words ("Orders", "Live fleet"). Captions are shown under the image.
- Save as WebP, under 250 KB each. Images are shown whole, never cropped, so a different ratio only adds borders.

## Before publishing

- Does the client allow it to be shown? Blur names and personal data in screenshots.
- Can you explain every number in "Key numbers"?
- Open the project page on a phone and check the carousel and the buttons.

## Featured on the home page

Home shows projects with "show in overview" on, ordered by the overview order set in the manage-projects screen. Keep it to three.
